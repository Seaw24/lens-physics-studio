# Lens — the physics of a basketball shot

A working hackathon prototype that turns a real basketball clip into a learning loop: observe, predict, experiment, explain, and recall.

## Run locally

Requires Node.js 22 or newer.

```sh
npm install
npm run dev
```

Open http://127.0.0.1:5173. The local API runs on port 8787. Both bind to localhost.

```sh
npm test
npm run build
npm start
```

After a build, `npm start` serves the compiled site and API together at http://127.0.0.1:8787. No deployment or cloud resources are created by these commands.

## The demonstration

1. On **Your day**, watch the user's basketball recording. The useful shot is approximately 14.2–15.4 seconds into the 48.6-second file.
2. Open **Explore this event**. Only the extracted 2.3-second shot (13.5–15.8 seconds in the original) plays, uninterrupted. It then returns to the prepared frame at 14.70 seconds. Playback controls are bounded to this event.
3. Answer the coach inside the video stage. Choose **There is no net force** to demonstrate a common misconception. Feedback reveals a gravity arrow anchored directly to the ball. Two more questions cover vertical velocity at the ideal apex and horizontal velocity during descent.
4. Open **Play with physics** and use **Pause at the top**. Vertical velocity becomes zero; horizontal velocity and downward acceleration remain. Change launch angle, speed, and height. Switching back preserves the coaching answer and reflection draft.
5. Open **Your course** to see a course-aware starting check. The prepared projectile notes are mapped into topics and prerequisites; students can replace them with a PDF analyzed by Amazon Bedrock or paste course text for local mapping. A five-question diagnostic reports skill-level evidence and recommends a next lesson without claiming permanent mastery.
6. Open **Physics lounge** for general physics discussion, separate from the event questions. Demo answers cover forces, energy, torque, momentum, waves, units, and basic circuits. All prepared responses are labelled.
7. Explain in your own words and save to the notebook. Replaying the event preserves the current question or reflection. The saved explanation persists in this browser and can be exported as Markdown.
8. **Practice & recall** offers three transfer questions: a volleyball at its apex, horizontal motion, and different ball masses.

**Present demo** contains a short presentation guide. **Replay discovery** demonstrates a prepared prompt after the shot. Toggle **I'm busy** to defer it. This is an explicit availability control, not inferred attention, gaze tracking, or a live detector.

**Guide & about** introduces the website, walks through the learning loop, explains the separate roles of the coach and lounge, and offers a downloadable product brief (`public/lens-product-brief.md`). The guide also describes the limitations and how to replay, change speed, and preserve work.

## What is real, prepared, and hypothetical

| Part               | Implementation                                                                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Video              | Real 1080×1920, 30 fps, 48.6-second file supplied by the user. Original remains unchanged.                                                                                                                                    |
| Ball markers       | Twelve manually reviewed image positions from 14.2–15.3 s, linearly interpolated between samples. Not generated by AI; no camera stabilization or physical scale calibration.                                                 |
| Event coaching     | Real trimmed video with three prepared questions. Teaching frames at 14.70 and 15.00 s have manually positioned conceptual arrows. The near-apex frame is approximate because the camera moves.                               |
| Course             | Fixed sample PHYS 2010 lesson with projectile-motion notes.                                                                                                                                                                   |
| Course diagnostic  | Local mapping for pasted text, plus Bedrock document analysis for one PDF up to 15 MB. Both paths produce a five-question starting check, misconception feedback, and a recommended next lesson. PDF bytes are not persisted. |
| Simulation         | Analytical projectile equations with constant g = 9.81 m/s². No air resistance, spin, or collisions. Controls are hypothetical values, not estimates of this player's shot.                                                   |
| Demo tutor         | Deterministic coaching for supported concepts. Explicitly labelled “Demo tutor.”                                                                                                                                              |
| Live tutor         | Server-side Amazon Bedrock Converse adapter with lesson, observation, model values, and recent chat context. Requires credentials.                                                                                            |
| New-video analysis | Browser samples low-resolution frames; Bedrock proposes relevant moments and approximate object anchors. Requires credentials. Sparse frames cannot establish accurate speed or acceleration.                                 |
| Notebook           | Local storage, editable by revisiting a lesson; Markdown export. Reflection quality is not automatically graded.                                                                                                              |
| Review             | Three prepared transfer questions with deterministic answer checks. Session-level attempts are not a mastery score.                                                                                                           |

SVG diagrams explain ideal physics in the simulation and directly over paused real footage. The original uploaded recording is unchanged. Full frame-specific coaching is prepared for this shot; uploaded clips retain the simpler investigation workflow.

## Connect Amazon Bedrock later

The user chose demonstration mode for now. Live AWS calls have not been verified in this workspace.

1. Copy `.env.example` to `.env`.
2. Add temporary workshop credentials: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_SESSION_TOKEN`, or select an existing `AWS_PROFILE`. A Bedrock API bearer token is also supported via `AWS_BEARER_TOKEN_BEDROCK`.
3. Set `AWS_REGION` and a model available in that region. The default is `amazon.nova-lite-v1:0` in `us-east-1`. Nova Lite supports image and document inputs; a text-only model cannot analyze video frames or course PDFs.
4. Restart `npm run dev`, open **Studio settings**, and check the connection.

No keys are stored in the browser or committed to the project. `.env` is ignored. The account must permit the required Bedrock model invocation. Configured does not guarantee that credentials are valid; authentication/model errors are shown when a request runs. Workshop accounts are temporary, according to the event resources.

Official references: [Converse API with Amazon Nova](https://docs.aws.amazon.com/bedrock/latest/userguide/bedrock-runtime_example_bedrock-runtime_Converse_AmazonNovaText_section.html), [Nova image examples and limitations](https://docs.aws.amazon.com/nova/latest/userguide/modalities-image-examples.html).

## Data flow

- Local playback uses a browser object URL for added files. The entire video is not sent to the server.
- “Analyze sampled frames” decodes up to 90 candidate frames locally, then selects at most 20 using uniform temporal coverage and image-change ranking. Image change is a sampling cue, not a physics inference.
- The API receives only selected JPEG frames and timestamps. Audio is not included. UI explains this before analysis.
- Tutor requests contain the current observation, hypothetical model state, and up to ten recent chat messages. No notebook upload is performed.
- Course PDF analysis accepts one PDF up to 15 MB. The browser sends its bytes to the local API, which forwards them to Bedrock through the Converse document interface under a neutral name. PDF bytes are discarded after the request; only the validated course map and five diagnostic questions are stored in browser storage.
- Uploaded documents are treated as untrusted evidence. Instructions inside a PDF cannot change the server prompt or response schema. The student’s local filename is not sent to Bedrock.
- The Express API validates inputs, restricts browser origins to the local prototype, sets no-store headers, limits requests, and uses bounded cloud request timeouts. This is a local hackathon application, with no production authentication or cross-device synchronization.

## Source map

- `src/App.tsx`: navigation, recording, course, notebook, review, presentation, and connection dialogs.
- `src/VideoPlayer.tsx`: playback, slow motion, prepared markers, and accessible annotation controls.
- `src/CoachedInvestigation.tsx`: coaching/lab workspace with optional general discussion.
- `src/CourseDiagnostic.tsx`: local course-material intake, course map, diagnostic flow, skill signals, and recommended route.
- `src/EventCoach.tsx`: isolated event playback, prepared pauses, on-video diagrams, inline questions, and reflection.
- `src/PhysicsLounge.tsx`: general physics discussion, with explicit demo/Bedrock sources.
- `src/Guide.tsx`: optional introduction, instructions, FAQ, and product brief download.
- `src/coaching.css`: responsive coaching stage and guide visual design.
- `src/Investigation.tsx`: legacy generic investigation flow retained for other recordings.
- `src/Projectile.tsx`: animated projectile simulation and vector readouts.
- `src/api.ts`: local frame selection and API client.
- `shared/physics.ts`: course, prepared evidence, equations, answer checks, and demo coaching.
- `shared/coaching.ts`: extracted event bounds, question frames, options, and overlay positions.
- `shared/generalTutor.ts`: topic-specific demo responses for the general discussion lounge.
- `shared/diagnostic.ts`: supported physics-topic signals, question bank, grading, and next-lesson selection.
- `server/index.ts`: Bedrock tutoring and frame-analysis adapter.
- `tests/physics.test.ts`: physical invariants, landing/apex behavior, and answer-validation cases.
- `tests/coaching.test.ts`: event time boundaries and separation of general discussion from event coaching.

The project also retains the earlier conceptual blueprint and reusable force/torque models from the original scope. The visible demonstration is now basketball projectile motion.

The prototype targets the Learn track of **Minds & Machines: AI in Education**, using the resources the user opened in Chrome. It demonstrates the connection between a real-world context, course-grounded tutoring, an executable model, and evidence of student reasoning.
